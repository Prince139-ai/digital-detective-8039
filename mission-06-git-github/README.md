## 4. my understanding

### task 6.1 - understand the basic git workflow

| git operation | what it does in your own words |
| :--- | :--- |
| check repository status | shows modified, untracked, and staged files |
| stage selected changes | marks file changes to include in the next commit |
| create a commit | saves snapshot of staged files into git history |
| view commit history | displays list of past commits and messages |

difference between staging and committing:
staging is choosing which changed files you want to save
committing is actually saving that snapshot permanently into git history

### task 6.2 and 6.3 - create branch and pull request

what a branch and pull request are:
a branch is an independent copy of code where you can work without affecting the main project
a pull request is asking team members to review and merge your branch changes into main
these tools help teams work on different features together without breaking existing code

### task 6.4 - build your git command glossary
- initialise a repository: git init creates a new git repository in folder
- check status: git status checks which files are modified or staged
- stage changes: git add stages files for next commit
- commit changes: git commit saves staged changes with a message
- view history: git log shows list of previous commits
- create or list branches: git branch shows existing branches or makes a new one
- switch branches: git checkout or git switch moves to another branch
- publish changes: git push uploads local commits to github
- retrieve remote changes: git pull downloads latest changes from github to local computer
